# 封装内内存（node16-31）：ACPI 表解析 + 通道结构实测

> **这份文件是什么**：`docs/hw-report-20261104-144311.txt`（同一台机器、同一天）的
> 补充。那份采集脚本把 SRAT/SLIT/HMAT 原表存了下来却没解析；本文补上**表内容解析**
> 与**封装内内存的带宽/延迟实测**，用来结掉两份内存文档里两个长期"未结论"的欠账。
>
> **数据来源**：
> - ACPI 三张表：root 采集（本地目录 `hw-raw-20261104-161534/`，2026-11-04 16:15，
>   被 `.gitignore` 排除；复现方式见文末命令），不含序列号；解析器 =
>   `tools/parse-acpi-hw.py`。
> - 带宽/延迟：`benchmarks/memprobe` + 内嵌 `memwin`（同一时间窗口法），2026-11-04
>   15:45-16:10 之间在共享机上跑，实测脚本 = `tools/finish-hw-open-items.sh` 的 B 段。
> - 口径：延迟 = 64MB 足迹的依赖链（`chase 65536`）；带宽 = 每进程 128MB 缓冲区、
>   2s 固定窗口、取两次最好；每个 node 绑自己的 32 条核（socket0 用 CPU 0-223 的分片，
>   socket1 用 304-527 的分片）。

## 三、怎么复现

```bash
# 1) root 跑一遍：导出三张 ACPI 表到 hw-raw-open-items-<时间戳>/，再跑 B 段实测
sudo tools/finish-hw-open-items.sh

# 2) 只解析表（非 root 也能跑，只要目录里的表可读）
python3 tools/parse-acpi-hw.py hw-raw-open-items-<时间戳>

# 3) 想看单点，用上面同一条 memprobe + 固定核段
numactl --physcpubind=0-31 --membind=17 ./benchmarks/memprobe chase 65536 2000000
```

脚本会自己打印 raw 目录与报告路径；`hw-raw-open-items-*/` 与根目录的
`hw-report-open-items-*.txt` 都在 `.gitignore` 里，只有本文这份摘要在版本库里。
