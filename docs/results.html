channels_last/置换布局的输出曾恒分配为 NCHW 连续，E2E 静默打断格式传播链。 布局修复（tmp+copy_）先止血，R10 直写（消掉那一趟拷贝）完成反超。

04真实 workload 对拍（§2.9.4）

两进程 x[idx] 全链路（含 dispatcher/输出分配/normalize），这才是集成收益口径。

05生产形态：小 K + 6–19 线程（§2.10）

与 §2.9 正交的一条轴：K=512–55296、线程 1/6/12/19，全部走真实 x[idx]。 旧基准的 K=2M/10M 与 1/608t 是两个端点，从没测过这一段。

为什么掉：桶化路径 26% 的每元素成本不随线程缩小（两趟 parallel_for 夹串行建表， 2026-11-03 起已拆两块）；4B gather 每线程每元素 19.9ns，停在 SVE gather 微码下限，aten 13.1ns （4MB 源落进 19 核的 L2 聚合）。机理全文见 degradation-analysis.md §6.5。

06路由成本分层探针（§2.13）

回答“路由条数会不会抬高每次调用的固定开销”——不会：K≤4096 且下标连续的形态 全被入口快路径吃掉，根本走不到路由链。

短调用（chain，K≤4）

连续下标 6.90µs（走 small_single）；非连续 9.75µs（+2.85µs = normalize + 通用路由）； Python int 下标参照 5.32µs。if 链本身量级<2.85µs，Python/绑定侧差 1.58µs 反而更大。

语料路由分布（census，26 形态）

small_single 15 · 无专属计数器 6 · rowcopy_raw 3 · single_1d_sve 2。 实际只用 4–5 条路，其余是退化兜底——“删路”要看 trace 覆盖，不能只看条数。

07路径矩阵：每条路值多少（§2.14）

按“路径 × 规模 × 线程”组织（产品口径 = vs aten），另有“同工作量只差一个谓词”的兄弟对照。 101 个测量点全部与路由计数器一致（0 处 EXPECT MISMATCH）。

08H1 行拷贝软件预取（§2.18）

唯一的大杠杆：提前 D 行发 prfm，把“依赖链等延迟”改成“多条在飞”。

稳态与固定成本（§2.18.5，1t A=16 K 扫描拟合 t = F + c·K）： 每行稳态 80.0 → 19.4 ns（4.1x）（探针纯拷贝下界 11.4，差 1.7x = 检查/地址计算/预取记账）； 每调用固定成本 F ≈ 0.54ms 与预取无关——K≲32768 时把 ns/行 抬 2–3 倍，小 K 的账不在行循环里。

09桶化输出段：批量化证伪，两刀结构改动证真（§2.21）

前提验证：隔离探针 bucketprobe 专门测“批量化能不能到探针下界”。

10SVE 的形状实验（§2.23，2026-11-05）

用真发指令 + 逐 lane 校验的方式回答“一条 gather 到底取几个元素、每次访问多贵”。

一条 gather 取几个

1B/2B/4B 各 16 个元素、碰 16 条 line（搬进 1024B）；8B 是 8 个、8 条 line。 关键：子字 gather 只能用 32 位下标——“64 lane”只存在于字节视角。

每次访问多贵（256MB 源）

1B 7.68ns / 2B 8.09ns / 4B 8.68ns / 8B 5.67ns——与元素宽度几乎无关， 有用带宽正比于宽度（0.13/0.25/0.46/1.41 GB/s）。这就是 1B/2B 干脆不写 SVE 内核的理由。

11硬件探针速览（§2.16）
