SVE512 内核详解：谁被选上、为什么快、边界在哪

本文把 docs/kernels.md 的内核选择逻辑画成流程图， 把每个内核族的性能特性画成卡片。性能数字是历史轮次实测（多为 T11/T13/T15）， 当前值一律以 RESULTS.md §2.9 为准。

机器：鲲鹏 920F（SVE 512-bit，VL=64B）｜ 所有 SVE 内核以 -msve-vector-bits=512 编译、运行时 sve_512_ok() 门控

01一句话：三个量决定路由

A 大走 RowCopy ｜ A==1 走 PureGather ｜ K 小走 gather_direct / small_single
A = 每次访问连续元素数（dims_after 后缀乘积）· K = 索引元素数（broadcast 形状积）· B = 广播出的前导行数（dims_before 前缀乘积）

名词速览

SVE / VL

ARM 可伸缩向量扩展；VL = 向量长度（本机 512-bit = 64B），svcntb()==64。

gather

按地址向量取元素（随机）；svld1_gather_* 一条指令最多 8-16 个元素。

rowcopy

用 ld1/st1 搬连续一段；把 64B 行放大摊薄到多个有用字节。

prefetch

预取：提前把 cache line 拉进缓存掩盖延迟（H1 是本仓唯一兑现的大杠杆）。

NT

non-temporal：绕过缓存直接写内存；实测无收益（RESULTS §2.17.2），默认关。

bucket（桶化）

值域 ≤2048 时先建"值→行"查表，把随机 gather 变成顺序查表。

linearize

多维下标换一维偏移；两遍模型的第一遍，raw 路径专门跳过它。

raw 路径

直接消费原始下标张量、不经过 linearize 的短路内核统称。

04PureGather 族：A==1 的随机 gather

4.1　8B 元素（f64/i64）——主要收益来源

核心指令

svld1_gather_u64index_f64(pg, base, off)：u64 元素偏移自动缩放，svcntd()==8（每向量 8 个 8B）。主循环双发：先 svprfd_gather 预取前 16 个向量位置，再 gather 当前向量。

带宽实测（T11 定点，1D f64 K=2M）

hpc 1/2/4/8/16/32t = 0.61 / 1.08 / 2.09 / 3.91 / 6.87 / 6.80 GB/s，对 aten 1.03–1.26x；K=10M 时 32/36t 9.1–9.2 GB/s（aten 4.5–4.8）。

4.2　4B 元素（f32/i32）——行放大 16x 的硬墙

为什么 8B 路径不受影响：同样条数的 line 携带 2x 有用字节 （8B 行放大 8x vs 4B 16x）。4B 大 K 大值域的可行方向是减少行流量 （小值域桶化、预取、行 gather），而不是换指令。

4.3　T15-C：大源直连 pure_gather_sve_4b_i64idx

ACLE 没有"32 位数据的 64 位下标 gather"，T15-C 用 uzp1 抽 i64 低 32 位 收窄成 u32 元素偏移，补上 L3/DRAM 驻留源的入口：标量乱序窗口摊不掉大源延迟 （~19ns/元素），SVE 每迭代 8 路在飞只要 ~10ns。

门控条件

1D 单索引 A==1 · 原始 i64 下标 · dtype∈{f32,i32} · stride0==1 · size<2³² · SVE512 · 线程数>1 · 源>512KB（L2 实测 768KB，取保守界）

实测收益

2.22x

1D f32 K=10M idx64，8t（hpc 绝对时间 −40%）；8–36t 1.44–2.22x

为什么不全走

小源与 1 线程不走：小源标量 L1 命中 ~7.1ns/元素 vs SVE 微码/发射下限 ~18ns；1 线程仍走标量单遍。交叉点 ≈ L2。

05RowCopy 族：A>1 连续块（最强收益）

条件：A>1 && after_contiguous && A≥4 && dtype∈{f32,f64}。元素 out[p·A+c] = src[row_off[r]+idx[k]+c] 变成一段连续 A 拷贝——只读一次 idx， A 个元素连续向量化。这是 S1 spconv / P1 图消息 ~4x（1t）/ ~1.9x（38t）的来源。

三个变体

§3.1 M1 raw rowcopy（T2）

跳过 linearize，直接遍历原始下标（i32/i64），内联边界检查 + 负索引归一。门槛：A≥4096 或 A<16 或 (A≤64 且 B·K≤65536)。省一次 broadcast 解码 + K×N 写入，单索引大块收益显著：M1 权重块 1 线程 2–13x。B==1 单独分支去 p/K、p%K，A=8/15 多线程再 +1.2–1.4x。

§3.2 strided-rows raw（T12）

after 非连续但 col_off 存在 ≥4 连续 run：make_col_runs 合并成 {dst_col, src_off, len}，每行一次基址 + 每 run 一次块拷贝。例：尾维 [64,200,16] permute(1,0,2) → A=1024 从 1024 次标量拷贝变 64 次 64B 拷贝，1t 2.23x / 8t 1.71x。run=1 纯转置不启用。

§3.3 多索引 fused（T12）

多索引 && after_contiguous && A≥4 && f32/f64 && ≥16t：跳过 linearize，直接按多索引解码行地址；高线程避免两遍模型的串行写/读。n>65536 或广播/非连续形态回退。

门槛放宽史：T1 从 A≥16 放宽到 A≥4（微基准 A-sweep 显示 A=4–16 短行 1t 即 1.1–17x）； T12 补 A<16 多线程 raw；T15 放行 A 17..64 小 K（B·K≤65536）。

06其余内核：快路径与兜底

§5 gather_direct（K<1024）

A==1 单索引全长连续 → 预校验 + 紧凑标量循环；省 linearize 的分配与一遍遍历。RESULTS §2.14.2：丢掉这个入口要多花 8.28x（8t）。

§4 dispatch_scalar（兜底）

2B/1B/complex/非连续小块的统一单遍标量回退（T11 起）。宁可一遍慢，不要两遍快——避免线性化把固定成本翻倍。

§9 gather_mask（T8）

单 bool mask 连续：单遍压实，跳过 nonzero() 物化。P3 mask C=16 1t 1.77x（RESULTS §0）。非连续 mask 回退 nonzero（0.79–0.98x，R2 待做）。

§10 small_single / T13 small_multi

单整数下标 K≤4096 连续（6.90µs）或多索引同 shape n≤65536：normalize 之前直接预校验偏移 + memcpy，根本不进路由链（RESULTS §2.13.1）。

07SVE 的形状事实（RESULTS §2.23）

用真发指令 + 逐 lane 校验回答"一条 gather 到底取几个元素"——这决定了 1B/2B 值不值得写 SVE 内核（结论：不值得）。

08预取与 NT 决策（Task 8 结论）

预取：唯一的大杠杆

H1 行拷贝预取兑现（对 aten 1.6–2.6x → 2.1–6.0x）；H6 桶化记账批量化实测无效已收口（headroom §1.6）。4B 向量路径的 PREFETCH_DIST 预取仍是未兑现方向（degradation §6.5.6-3）。

NT：实测无收益

非临时存储 vs 普通 store 差 ≤1.5%（噪声内；RESULTS §2.17.2：36t 141.1 vs 139.7 GB/s）。写侧省下的 RFO 流量不构成瓶颈。HPC_INDEX_NT 默认关。

线程并行

at::parallel_for 分块，adaptive_grain(K) 控制 chunk 大小。 注意 adaptive_grain 只控粒度不减线程数——"A=1 且 K/线程<2048 时减少有效线程" 仍在缓解方向清单里（degradation §6.5.6-2）。

09修改内核时的门槛清单（防回归）

  • 新内核先问：是否跳过 linearize？ raw 短路是收益主体，两遍模型只作兜底。
  • 新门槛先跑 A-sweep / K-sweep / 线程扫描 三件套，别只看单点（T1 放宽到 A≥4 就是这么来的）。
  • 4B 大 K 形态：禁止用"换指令"思路优化——瓶颈是行流量；先问能否减少 line 访问数（桶化/行 gather）。
  • 小行宽（≤64B）优先 memcpy，别上 masked SVE（谓词构造开销更大）。
  • 任何"单算子 N 倍"结论必须附 A=1 + K∈[4096,55296] + 6–19t 一族的数字（degradation §6.5.4 端点错觉）。
  • 改路由要同步三处：op.cpp 分支、kernels.md 速查表、architecture.md 伪代码。
