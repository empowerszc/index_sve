# docs 可读性重排——设计文档

- 日期：2026-10-29
- 状态：待确认
- 范围：`README.md` + `docs/` 下全部正文文档（不含源码、不含 `benchmarks/RESULTS.md`）
- 方案：A（可读性重排），已与需求方确认

## 1. 背景与目标

### 1.1 现状

`docs/` 现有约 7000 行正文，技术内容扎实、交叉引用完整，但读起来更像**查表
手册**：大量表格、括号、代号与「见 §x.y」打断，当前数据与历史数据同屏，单句
常带 3-4 个括号。第一次读的人很难建立主线，老读者也要反复判断"哪个数字是现在
的"。

### 1.2 目标

让文档**顺着读能读懂、跳着查能查到**，且不丢失任何技术事实与历史可追溯性：

1. 每篇有统一导读块：这篇讲什么、读完能回答什么、本篇用到的代号。
2. 正文先给结论与直觉，再给细节；长句拆短，括号信息外移。
3. 正文只保留"当前状态 + 与当前相关的原因"；历史数据下沉到文末附录或 archive。
4. 术语与格式统一；长文有目录。
5. `docs/index.md` 从"巨型表格"改成"按目标选阅读路径"的入口。

### 1.3 非目标

- 不改任何技术结论、数字、代码行为、测试。
- 不重写 `reference/` 的深度技术内容（只统一目录、术语链接与格式；这两篇**不套用**统一导读块，验收时也不算「正文」）。
- 不合并或删除文档文件（那是方案 B，本轮不做）。
- 不改 `benchmarks/RESULTS.md`（它是数字唯一出处）。
- 不改变 `file:NNN` 行号锚点的语义与校验方式。

### 1.4 反目标（做了就算失败）

- 为了"顺"删掉关键技术细节或根因论证。
- 引入与 `benchmarks/RESULTS.md` §2.9 不一致的新数字。
- 大范围移动/改名文件，导致仓库内相对链接失效。
- 把历史数据从"可追溯"变成"找不到"。

## 2. 约束

1. **数字口径**：当前值的唯一**矩阵**出处是 `benchmarks/RESULTS.md` §2.9。文档正文只写
   代表值 + 指针，不复制全矩阵。专项文档（如 `output-layout.md` §8 的 R10 前后对照）
   可以为解释自身机制保留必要的前后对照，但不视为新的数字出处，也不得再被其他正文复制。
2. **行号锚点**：改完源码相关引用后跑 `python3 tools/check_doc_anchors.py`，
   保证 `file:NNN` 仍落在含对应符号的行上。
3. **归档规则**：整篇被取代的快照才进 `docs/archive/`，规则见
   `docs/archive/README.md`；局部历史数据留在原文并标 `【历史·<轮次>】`。
4. **中文写作**：保留现有代号体系（S1/P1/M1/T0-T15/R1-R9 等），不另造新代号。
5. **兼容现状**：现有文档间链接、`docs/index.md` 维护约定、README 阅读路线都
   必须继续成立。
6. **小节编号稳定**：默认不改现有小节编号（`§5.8`、`§2.9` 之类被大量跨篇引用）。
   确需移动内容时，在原位置留一行「原 §x.y，见 §a.b」指针，并全仓 grep 更新引用；
   `archive/` 内容冻结，但允许更新其中的路径/编号指针（不改内容）。

## 3. 方案取舍

| 方案 | 做法 | 取舍 | 结论 |
|---|---|---|---|
| **A 可读性重排** | 保留文件与事实，加导读、拆长句、历史下沉、统一术语格式 | 改动大但机械，风险低，链接不动 | **采用** |
| B 重构文档体系 | 合并重叠文档，建立单一叙事线 | 收益最大，但链接大改、细节易丢 | 本轮不做 |
| C 轻量润色 | 只加导读/目录/修格式 | 最快，但历史混排的根因仍在 | 不采用 |

## 4. 写作规范（本轮的"施工图"）

### 4.1 统一导读块

每篇正文（含 README）开头放同一形状的导读块，放在标题之后、第一个 `##` 之前：

```markdown
> **这篇讲什么**：一句话说明主题与它解决的问题。
> **读完你能回答**：3-5 个具体问题（用"？"结尾）。
> **本篇代号**：S1/P1/M1/shortq…（首次出现给一句白话，完整表见
> [glossary.md](glossary.md)）。
```

### 4.2 正文结构

- 每节第一句先给结论，再展开；节标题尽量是"问题/结论"而不是名词堆叠。
- 一段只讲一件事；超过 4 行的段落考虑拆成列表或小表。
- 长句拆分规则：一句话最多一个主括号；第二个括号内容改为表格列、脚注或
  「延伸阅读」。
- 表格前必须有一句"怎么读"；表格后必要时给一句"所以呢"。

### 4.3 术语与代号

- 术语首次出现给一句白话，之后统一用同一词：
  - 主语统一用「本算子」，需要指包时用「`index_sve`」，不混用「hpc」。
  - 原生实现统一用「aten」，需要强调参考值时用「true aten」。
  - `ratio` 统一写「加速比」，并首次说明 `>1 = 比 aten 快`。
  - `line amplification` 统一写「行放大」。
- 代号首次出现给含义或链到 glossary；多义代号（如 M1）在首次出现处显式区分
  「机制 M1」与「负载 M1」。
- `R10` 是当前轮次代号（2026-10-29 布局直写轮），与路线图优先级 `R1-R9`
  无关；在 glossary 与首次出现处写明，不重命名任何代号。

### 4.4 当前与历史

- 正文只写当前结论（R10），历史值放到文末「附录：历史数据」并标轮次，或整篇
  进 archive。
- 每个实测表前保留「数据轮次」行（沿用现有约定）。
- 同一数字不在多篇正文复制；需要时写代表值 + 指向 `benchmarks/RESULTS.md`。
  允许保留代表值的「摘要位」只有三处：`README.md`、`summary.md`、`performance.md`；
  其余正文只写结论与指针。附录不计入重复。
- 慢场景家族统一按 `RESULTS.md` §2.9.1 口径写「五个可复现家族 + 噪声级单格
  （另计）」，不再用「六个家族」把噪声算作一类。这是对齐唯一出处，不是改结论。

### 4.5 交叉引用

- 正文少用打断式括号引用；每节末尾集中一行「延伸阅读：…」。
- 跨文档引用统一写成「文档名 + 小节」，避免裸 `§x.y`（除非同篇）。

### 4.6 格式

- 超过 300 行的文档加目录（`## 目录` + 锚点链接），放在导读块之后。
- 标题层级统一：`#` 一篇一个；`##` 主节；`###` 子节；不再出现 `####` 超过
  两层。
- 代码块标语言；表格统一首行表头 + 分隔行。

## 6. 验收标准

1. 每篇正文首屏都有统一导读块；长文有目录。
2. 抽读 `architecture.md`、`performance.md`、`degradation-analysis.md`：
   正文不再把历史矩阵与当前结论混排。
3. 同一代表数字最多出现在 3 篇正文（允许的摘要位：`README.md`、`summary.md`、
   `performance.md`）；附录不计；区间值按一个条目算。
4. `python3 tools/check_doc_anchors.py` 通过。
5. 仓库内相对链接全部有效（写脚本检查）。
6. `git diff` 中不出现技术结论/数字被改错；抽查 10 处数字与 RESULTS §2.9 一致。
7. 不删除任何根因论证；历史内容可在附录/archive 中找到。

## 7. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 大规模改写引入事实漂移 | 逐篇改、逐篇 diff；数字只从原文搬运，不新造；抽查对照 RESULTS |
| 移动历史内容导致引用失效 | 先 grep 引用；保留锚点或在原位置留指针；链接检查脚本 |
| 行号引用因源码无关的编辑漂移 | 不改源码；`check_doc_anchors.py` 兜底 |
| 改动过多难以 review | 按文档分批提交/分批给你看；每批先给 diff 摘要 |

## 8. 留给实施者的决定

- 导读块的精确措辞、每篇"读完能回答"的具体问题。
- 历史附录的切分粒度（按轮次/按家族）。
- 长文目录的锚点命名。
- 分批顺序（建议先入口文档，再性能组，再编年史/参考）。

以上均不改变本设计的结构与验收标准，由实施者按现场情况决定。

   `summary.md`、`performance.md` 三篇；其余正文只写结论与指针；附录不计；

   是该专项的实测细节（`1.45-2.54x` 的 owner），不算摘要复制。`summary.md`
   §6.2 的 8 线程表保留（它是"给同事的系统介绍"的核心），但不再在
   `status.md`/`fallback-analysis.md`/`integration.md` 正文复制。
2. **`status.md` 纳入范围**：见 §5 新增行。它复用现有「30 秒现状」作导读，
   不叠加第二块；§2 变更日志与 §5.2 逐轮历史保留在文末/原位（快照职责），
   但正文当前结论只留 §5.1 一行 + 指针。
3. **小节编号**：默认保号；确需移动时留「原 §x.y」指针并全仓 grep 更新；
   `archive/` 内容冻结，只允许更新其中的路径/编号指针。`check_doc_anchors.py`
   仍只校验源码行号，跨篇 `§` 引用由 grep + 人工清单兜底。
4. **`reference/` 不套导读块**：它们不是本轮「正文」，只统一目录、术语链接与

   「五个可复现家族 + 噪声级单格」对「六个家族」——统一为前者，并把
   `performance.md` 开头仍指向 §2.4 的旧句改为 §2.9。这属于对齐唯一出处，

6. **`R10` 与 `R1-R9`**：不重命名。在 `glossary.md` 加一行
   「R10 = 当前轮次（2026-10-29 布局直写轮），与路线图优先级 R1-R9 无关」，
